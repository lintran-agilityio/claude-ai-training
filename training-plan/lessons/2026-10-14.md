## 1. Projects

- **Purpose:** A dedicated workspace with persistent knowledge, custom instructions, and optional team collaboration. Every chat inside a project automatically uses that knowledge and follows those instructions.
- **RAG (Retrieval Augmented Generation):** When project knowledge nears the context window limit, Claude stops loading everything and instead retrieves only the relevant parts. Capacity grows up to 10x with no change in how you work.
- **Sharing (Team and Enterprise):** Three permission levels: *Can view* (read and chat), *Can edit* (change instructions and knowledge, manage members), *Owner* (full control, decides visibility).
- **Best practices:**
  1. Start focused, then expand.
  2. Keep knowledge current; outdated documents produce outdated answers.
  3. Write clear, specific instructions.
  4. Name documents descriptively (e.g., `Q4-2025-Sales-Report.pdf`).
  5. Reference documents by name when asking questions.
- **Developer tip:** Keep one project per codebase or feature (conventions, architecture, API specs, ADRs). Because retrieval is partial, avoid asking for a summary of everything at once; ask by section.

## 2. Artifacts

- **Definition:** A standalone output (document, deck, design, dashboard, prototype, working code) shown in its own window beside the chat. On paid plans, artifacts are saved in the Artifacts tab; on the Free plan they stay with the conversation.
- **Dedicated tools (beta, paid plans):** *Claude Design* (visual work, design-system aware), *Claude Slides* (presentations, export to PPTX/PDF), *Claude Docs* (collaborative living documents, export to Google Docs/.docx). They can convert into each other ("turn this doc into a deck").
- **Available on every plan:** dashboards, trackers, flowcharts, interactive pages, working code.
- **Artifact vs. file creation:** An artifact opens, updates, and is shared by link inside Claude. File creation produces a downloadable Word, Excel, PowerPoint, or PDF file.
- **Three ways to edit:** edit directly, comment on the exact spot (in Docs, @-mention Claude), or keep asking in the conversation.
- **Sharing:** Private by default. Permissions: view, comment, edit. Team and Enterprise keep links inside the organization unless an Owner enables External sharing.
- **Prompting tips:** Ask for the deliverable, not only the content; be specific; describe the end user; create the artifact after the discussion has built context; ask Claude to refresh embedded data when needed.
- **Prompt formula:** *what product + required content + end user + (optional) interactive behavior.*

## 3. Skills

- **Definition:** Folders of instructions, scripts, and resources that Claude loads to perform a specialized task in a repeatable way.
- **Two kinds:** *Anthropic Skills* (Excel, Word, PowerPoint, PDF creation; invoked automatically) and *Custom Skills* (your own workflows, such as brand guidelines or analysis methodology).
- **Enabling:** Requires *Code execution and file creation* (Settings > Capabilities), then Customize > Skills. On Team and Enterprise, an Owner controls the setting.
- **Usage:** Claude selects skills automatically from the request; output is typically a downloadable file.
- **Skill vs. artifact:** A skill defines *how* work is done; an artifact is the *product* you keep editing.
- **Developer tip:** Package repeatable team practices (code review checklist, bug report template, release notes format) as custom skills.

## 4. Connectors and MCP

- **Connectors** give Claude access to the tools you already use, so it can read data and take actions on your behalf, within the permissions you grant.
- **MCP (Model Context Protocol)** powers connectors. It is an open standard, often described as "USB-C for AI".
- **Two types:** *Web connectors* (cloud services such as Google Drive, Slack, Notion, Asana) and *Desktop extensions* (local, via Claude Desktop: file access, browser control, native apps).
- **Setup of a web connector:** find it, click Connect (Owners add it first on Team/Enterprise), authenticate, grant permissions, test with a simple request.
- **Security:** Permissions are scoped and can be toggled; Claude only sees what you can see; access is revocable at any time; install connectors only from trusted sources.
- **Using MCP in Claude Code (hands-on):** Browser control is possible through Playwright MCP:
  ```bash
  claude mcp add playwright -- npx @playwright/mcp@latest --user-data-dir=<profile-folder>
  ```
  A persistent profile keeps the login session, so credentials never need to be placed in prompts or files. Keep secrets out of `.mcp.json` and out of git.

## 5. Enterprise Search

- **Definition:** An "Ask {Org Name}" project in the sidebar, effectively a pre-built project for the whole organization, with instructions tuned for information gathering. It searches across connected tools and answers with cited sources.
- **Setup:** An Owner connects at least one Documents source and one Chat source (Email is optional) and names the project; each user then authenticates with their personal accounts.
- **Safety:** Results respect each user's existing permissions; conversations stay private; connected data is not indexed or stored separately.
- **Best for:** Catching up, policies and processes, onboarding questions, and cross-source research about the organization.

## 6. Research

- **Definition:** An agentic, multi-step investigation: Claude plans, runs many searches that build on each other, synthesizes the findings, and cites every claim. It takes minutes, not seconds.
- **Requirement:** Web search must be enabled (+ menu > Research).
- **Choosing the right tool:**

  | Need | Use |
  |---|---|
  | Comprehensive, cited, multi-source report | Research |
  | Quick, single fact | Web search |
  | Deep reasoning without external information (math, debugging) | Thinking |
  | Internal company knowledge | Enterprise Search |

- **Prompt tips:** State a specific goal, the structure you want, and constraints (budget, timeline, region). Ask Claude to help refine the prompt if unsure.
- **Developer tip:** Use it for technology comparisons (for example, E2E testing frameworks) and verify the cited sources before deciding.

## 7. Use cases by role and other ways to work with Claude

- **Use cases:** Claude applies across roles (sales, marketing, finance, HR, legal, research). The Use Case Gallery provides step-by-step guides. Equivalents for developers: sprint reports, bug-feedback analysis, reusable skills, understanding inherited code, onboarding guides.
- **Where Claude runs:**

  | Tool | Best for |
  |---|---|
  | Claude.ai | General tasks, research, writing, file creation |
  | Claude Code | Software development, codebase navigation, git |
  | Claude Cowork | Complex multi-step desktop tasks |
  | Claude Tag (Slack) | Team collaboration; can hand coding tasks to Claude Code from a thread |
  | Claude Design | UI prototypes; can hand off to Claude Code to build |
  | Claude for Microsoft 365 | In-place editing in Excel, PowerPoint, Word, Outlook |
  | Claude in Chrome | Browser tasks and automation (paid plans; use on trusted sites, low-risk tasks) |

## 8. Claude 101 recap: core principles

- **Prompt structure:** context + action + rules (format and style).
- **Iterate:** Treat the first answer as a starting point and refine it.
- **AI Fluency, four competencies:** Delegation, Description, Discernment, Diligence.
- **Collaboration mindset:** Claude is a collaborator, not a replacement; the best results combine your expertise and judgment with Claude's help.
- **Further learning:** *Claude Code in Action* (free course), *Introduction to Claude Cowork*, Use Case Gallery, Connector Directory, Anthropic Help Center.
